# Шахматное ателье — план развития

Актуализация: 2026-11-03. Это план **следующих проверок и улучшений**, не список завершённых функций. По исходным файлам в интерфейсе и JS указана версия 0.3.1; `dist/version.json` содержит исходный шаблон 0.3.0 и пересоздаётся GitHub Pages во время публикации. Версию опубликованного PWA проверять отдельно.

## Цель
Импортировать партию с минимальными усилиями и разбирать каждый ход: оценка качества, ключевые ошибки, сильная альтернатива и наглядное продолжение на доске. На iPhone должно быть удобно устанавливать и обновлять PWA.

## P0 — надёжный анализ
- Регрессионные примеры PGN (включая рокировку, взятие на проходе, превращение пешки, шах/мат, неполные партии). Критерий: корректное прохождение всех ходов без ложных ошибок.
- Проверить согласованность оценок Stockfish до и после хода, классификации и альтернативных линий. Критерий: численная оценка не противоречит показанному объяснению; неизвестное/непросчитанное отмечено.
- Сохранность партий при загрузке/перезапуске, отказе localStorage и обновлении PWA.

## P1 — удобный разбор ход за ходом
- На каждом ходе: качество, лучшая альтернатива, доска с продолжением, явный возврат к исходной партии.
- Для распознавания видео — проверяемые примеры поддерживаемых записей Chess.com, указание причины отказа и понятные советы по съёмке.
- Улучшить мобильное отображение диаграмм, навигации и загрузки на Safari iPhone.

## P1 — процесс проверки и обновления
- Добавить воспроизводимые smoke-тесты PGN, работы движка, service worker и проверки версии — без внедрения тяжёлой инфраструктуры до обоснования.
- Проверить GitHub Pages → обновление на установленном iPhone PWA, включая случай со старым кешем.

## P2 — расширение
- Больше визуальных шаблонов и ракурсов записи только после измерения качества распознавания на контрольных примерах.
- Более объяснимые шахматные подсказки с явным различием между движковой оценкой и авторским советом.
- Экспорт удобного разбора и сводки по повторяющимся ошибкам без передачи личных партий в облако.

## Что считать готовым
Не достаточно видеть корректный экран на одной демопартии. Нужны рабочий пользовательский сценарий, проверка крайних случаев и отдельная проверка iPhone PWA. Каждую новую функцию вести через GitHub Issue → отдельная ветка → PR.
